# Восстановление пароля

Перенесено из веб-проекта `S:\vojugo`: коммиты `2eb4fad` и `f5211f9`.
Вход в сценарий — «Забыли пароль?» на экране входа, маршрут `/forgot-password`.
Номер передаётся между экранами только в памяти.

После ввода телефона всегда показываются способы из API. Даже единственный способ
требует явного выбора; получение списка и окончание таймера не отправляют код.
Поддерживаются Telegram, email и SMS, изменение номера, альтернативные способы,
повторная отправка, проверка нового пароля и переход в кабинет своей роли.
Все восемь SVG скопированы из `src/assets/auth` веб-проекта без изменений.

## Сервер

Контракт сверён с OpenAPI backend 30.10.2026. Используется адрес
`EXPO_PUBLIC_API_BASE_URL` и четыре POST-запроса:

| Путь | Тело |
| --- | --- |
| `/auth/password-recovery/methods` | `{ phone }` |
| `/auth/password-recovery/code/send` | `{ phone, method }` |
| `/auth/password-recovery/code/verify` | `{ phone, method, code }` |
| `/auth/password/reset` | `{ new_password }` |

На Android/iOS токен из `/code/verify` хранится только в памяти и передаётся
в `/reset` как `Cookie: vojugo_access_token=...`, согласно схеме CookieRecovery.
Обычный Bearer-токен и автоматическое обновление сессии в этих запросах отключены.
Нативное автоматическое добавление cookies отключено, чтобы исключить старую сессию.
Только после успешного reset обычные access/refresh-токены из AuthResponse
передаются существующему хранилищу авторизации. Переход в кабинет запрашивает `/self`.
В браузере заголовком Cookie управляет браузер (`credentials: include`).

Обрабатываются `available_in`, `retry_after` и `Retry-After` (секунды/HTTP-дата).
После отправки пауза составляет минимум 60 секунд; более долгие серверные сроки
сохраняются. Время рассчитывается по абсолютному сроку, включая возврат из фона.
Секреты очищаются, незавершённые запросы отменяются при уходе со страницы.

Специальные коды ошибок перенесены из веб-адаптера. В OpenAPI пока описан общий
ErrorGeneral: наличие всех специальных кодов в реальных ответах не подтверждено.
Неизвестный HTTP 429 означает паузу, а не глобальное исчерпание попыток.

## Проверки

```sh
node --test tests/password-recovery.test.cjs
npx tsc --noEmit
npx expo lint
```

Тесты проверяют контроллер, реальные HTTP-обёртки с подменой fetch, обмен токенами,
ошибки, отмену, таймеры и редактирование кода. Реальные коды не отправляются,
пароли существующих аккаунтов не меняются. Проверку доставки и интерфейса на
физических Android/iOS нужно проводить отдельно на тестовом аккаунте.
